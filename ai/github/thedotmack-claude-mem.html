2. 主要用来干什么

解决一件让所有人恼火的事：换个会话，AI 就把前面的全忘了。

它在你干活的时候悄悄记录 AI 做了什么、决定了什么、下一步该干什么，用 AI 把这些压缩成摘要存起来；下次开新会话时，自动把相关的部分塞回去。你不用再手动复述"我们上次说到哪儿了"。

具体会记的东西：AI 用了哪些工具、改了哪些文件、做了什么决定、还剩什么没做。它还会自动生成带活动时间线的 CLAUDE.md 上下文文件。

典型场景：

  • 跨天做一个功能：昨天做到一半，今天开新会话，它自己知道上下文，不用你重新交代
  • 同时推几个项目：每个项目的记忆各自独立，切回去就接得上
  • 回溯"当初为什么这么改"：记录里有决策过程，不只有结果
  • 换工具也不丢：它不绑死 Claude Code，Codex、Gemini、Copilot、OpenCode 都能用

有两件事必须先说清楚，否则你会困惑：

一、它改名了。 README 第一行就写着「Claude-Mem 现在叫 Grok Mem」，但安装包的名字还是 claude-mem。你在网上会同时搜到两个名字指同一个东西。这个改名意味着项目重心可能在向 Grok 生态转，值得留意。

二、它需要给你的会话内容做 AI 压缩。 也就是说，你干活的过程会被送去给模型处理一遍。如果你的代码涉密，这一点要先想清楚。

技术上用了向量数据库和本地 SQLite 存储，支持 28 种语言的界面。

3. 为什么会火

它戳中了什么痛点

这可能是 AI 编程里最普遍、也最烦人的一件事：上下文一满，或者你关掉窗口，之前所有的来龙去脉就没了。 你得重新交代项目背景、重新说清楚上次改到哪、为什么这么改。做一个跨几天的功能，光"重新对齐"就要花掉不少时间和 token。

Anthropic 官方给的方案是让你手写 CLAUDE.md，但那是静态的——你得自己维护，而且它不知道"上次那个 bug 最后是怎么修的"。claude-mem 走的是自动路线：你干什么它记什么，需要时自己送回来。

为什么是它赢了

同类里它做得最"无感"——装上就工作，不用改习惯、不用手动存档。而且不绑死一个工具：Claude Code、Codex、Gemini、Copilot、OpenCode 都能用，这在同类里少见。

大家在夸什么

跨会话真的接得上、自动生成的上下文文件有活动时间线可回溯、支持 28 种语言界面。

（我原本想说"有人 fork 它接别的数据库，说明生态活跃"，但一查接口就打脸了：那个 customable/claude-mem 只有 4 个星、2026 年 1 月之后再没更新过。所谓生态并不存在。）

你必须留心的三件事

  1. 它改名了，而且改得有点尴尬。 README 第一行写着「Claude-Mem 现在叫 Grok Mem」，但包名还是 claude-mem。你搜资料会撞见两个名字。更值得琢磨的是：一个叫 Claude-Mem 的项目改名叫 Grok Mem，说明重心可能在往 Grok 生态转——如果你主力是 Claude Code，这个方向变化值得盯着。
  2. 你的工作过程会被送去给 AI 压缩。 这是它的工作原理决定的，不是 bug。涉密代码要先想清楚。
  3. 我没有找到成规模的批评。 这既可能是真没槽点，也可能是深度使用者还不够多。别把"没找到差评"读成"没有问题"。

什么时候该选它

  • 你就是想解决"换会话就忘"，别的都不想动 → 选 claude-mem。这是最直接的答案，装完即用，而且不绑死 Claude Code。
  • 你在自己写一个 AI 应用，需要给它加记忆能力 → 选 mem0。这两个不是竞品：claude-mem 是给你日常用的插件，mem0 是给你写代码时调用的库。选错方向会很痛苦。
  • 你想要的不只是记忆，还要规划、审查、安全那一整套 → 去看 ECC 或 SuperClaude。但反过来说：如果你只缺记忆，装那一整套是杀鸡用牛刀，而且它们本身也重。
  • 另外两个（claude-remember、customable 的 fork）我不建议用：一个太小众，一个基本已死，而且都没声明许可证。

一句话：记忆这件事上，claude-mem 目前基本没有对手。 它的风险不在竞争，在于那个改名——一个叫 Claude-Mem 的项目改叫 Grok Mem，重心往哪走值得盯着。

你亲测时重点看这几点

  1. 它到底记住了什么、忘了什么（最值得验）。跨一天做同一个功能，第二天开新会话，故意不交代任何背景，直接问"我们上次改到哪了"。看它答得多准。这是唯一能验证核心价值的方法，而现有评测全是教你怎么装。
  2. 中文项目上准不准。它靠 AI 压缩会话内容成摘要，中文代码注释、中文需求描述会不会被压丢？所有评测都是英文场景，这是块空白。
  3. 改名之后 Claude Code 这条线还维护不维护。去 issue 区看看最近的提交都在修什么——是在修 Claude Code 的问题，还是在往 Grok 那边加功能？这个观察本身就是内容。
  4. 额外花多少钱。它要调 AI 来压缩会话，那这部分是谁付？用你的 key 吗？一天下来多花多少？README 没说清楚，值得实测。
  5. 涉密项目能不能用。工作过程会送去给模型处理，验一下能不能配置成本地模型或者关掉某些目录。
